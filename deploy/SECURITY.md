# Запуск Diamond в интернете

## Сервер

1. VPS у хостинга с дата-центром в Казахстане (данные пациентов по закону хранятся в РК). Ubuntu 24.04, 1 ядро и 1 ГБ хватит.
2. Создать пользователя без прав: `adduser --system --group diamond`, файлы в `/opt/diamond`, владелец `diamond`, права `chmod 700 /opt/diamond`.
3. SSH: вход только по ключу (`PasswordAuthentication no`, `PermitRootLogin no`), `apt install fail2ban unattended-upgrades`.
4. Файрвол: `ufw default deny incoming; ufw allow OpenSSH; ufw allow 80,443/tcp; ufw enable`. Порт 8090 наружу не открывать.
5. `/etc/diamond.env` по образцу `diamond.env.example`, `chmod 600`. `HOST=127.0.0.1`, чтобы сервер был виден только nginx.
6. `diamond.service` в `/etc/systemd/system/`, `systemctl enable --now diamond`.
7. nginx: `nginx.conf` в `/etc/nginx/sites-enabled/diamond`, `diamond_proxy.conf` в `/etc/nginx/`. Сертификат: `certbot certonly --webroot -w /var/www/certbot -d diamond-dent.kz -d www.diamond-dent.kz`.
8. Первый вход: логин `owner`, пароль из `ADMIN_PASS`, система сразу потребует сменить. Сотрудникам завести отдельные логины с ролью «Администратор».

## Что защищает сам сайт

- Личные логины, пароли в виде PBKDF2-хешей, сессия в HttpOnly cookie, защита от CSRF.
- Блокировка входа на 15 минут после 5 неверных паролей (по IP и по логину).
- Лимиты: 5 заявок с одного IP за 10 минут, 200 заявок в час всего, лимиты на все запросы. Ловушка для ботов в форме.
- Заголовки безопасности и CSP: чужие скрипты не выполнятся, сайт нельзя встроить в чужую страницу.
- Загрузка только настоящих JPG/PNG/WEBP (проверка содержимого), листинг папок и служебные файлы закрыты.
- Журнал действий в админке, ежедневные резервные копии (14 дней), автообезличивание заявок старше 3 лет.

## DDoS

Сайт и nginx отсекают перебор и мелкие атаки с одного адреса. От настоящей DDoS-атаки (тысячи адресов, гигабиты трафика) защищает только сеть: включить защиту от DDoS у хостинга (у казахстанских хостеров обычно есть опция). Cloudflare тоже защищает, но пропускает трафик через зарубежные серверы, это стоит согласовать с юристом из-за требования хранить данные в РК.

## Резервные копии

Локальные копии лежат в `/opt/diamond/backups`. Раз в неделю копировать их на другой носитель (второй сервер или зашифрованное облако), иначе при поломке диска пропадут и копии.

## Юридическое

- В `privacy.html` заполнить жёлтые поля: юрлицо, БИН, адрес, контакты.
- Внутренние документы клиники (приказ об ответственном за персональные данные, перечень данных, правила доступа) готовит клиника или её юрист.
- Тексты политики и согласия перед запуском показать юристу: это шаблон, а не юридическое заключение.
